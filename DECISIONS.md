# Wildberries Manufacture - Принятые решения

## Введение

Этот документ фиксирует ключевые архитектурные и технические решения, принятые при разработке модуля Wildberries Manufacture. Все решения документируются для обеспечения прозрачности и последующей легкости поддержки.

## Архитектурные решения

### 1. Использование паттерна UseCase с DTO

**Решение:** Для всех бизнес-логических операций используется паттерн UseCase с DTO и Handler.

**Обоснование:**
- Четкое разделение данных и бизнес-логики
- Упрощение тестирования
- Повышение переиспользуемости компонентов
- Улучшенная читаемость кода

**Контекст:**
- Используется для создания и обновления заказов (WbOrders/New/)
- Используется для создания и обновления остатков (WbStocks/New/)

### 2. Асинхронная обработка через Symfony Messenger

**Решение:** Использование Symfony Messenger для асинхронной обработки данных.

**Обоснование:**
- Необходимость обработки больших объемов данных без блокировки пользовательского интерфейса
- Изоляция данных для разных профилей пользователей
- Возможность масштабирования обработки

**Контекст:**
- Сообщения для обновления заказов (UpdateWbOrders)
- Сообщения для обновления остатков (UpdateWbStocks)
- Планировщик задач использует Messenger для запуска задач

### 3. Отдельные транспорты для профилей пользователей

**Решение:** Каждый профиль пользователя имеет свой транспорт Messenger.

**Обоснование:**
- Изоляция обработки данных между профилями
- Параллельная обработка данных
- Предотвращение конфликтов данных

**Контекст:**
- `$profile.'-low'` - низкий приоритет для фоновых задач
- `(string) $profile` - обычный транспорт для профиля

### 4. Использование DBAL для аналитики

**Решение:** Для сложных аналитических запросов используется DBAL вместо ORM.

**Обоснование:**
- Высокая производительность при работе с большими объемами данных
- Гибкость в формировании сложных запросов
- Эффективность при работе с агрегационными функциями

**Контекст:**
- AllWbOrdersAnalytics
- AllWbOrdersGroup
- AllWbStocksBarcodes

### 5. Кэширование API ответов

**Решение:** Использование Symfony Cache для кэширования ответов от Wildberries API.

**Обоснование:**
- Оптимизация взаимодействия с внешним API
- Снижение нагрузки на сервер
- Улучшение производительности пользовательского интерфейса

**Контекст:**
- В API обертках (GetWbOrdersRequest, GetWbStocksRequest и др.)

## Технические решения

### 1. Использование AbstractHandler

**Решение:** Все UseCase Handlers наследуются от AbstractHandler.

**Обоснование:**
- Уменьшение дублирования кода
- Единый интерфейс для работы с репозиториями и валидацией
- Упрощение добавления новых функций

**Функции AbstractHandler:**
- `getRepository($entityClass)` - получение репозитория
- `persist($entity)` - сохранение сущности
- `flush()` - коммит транзакции
- `validatorCollection` - сбор валидаторов

### 2. Наследование от EntityState

**Решение:** Все сущности наследуются от EntityState.

**Обоснование:**
- Единый интерфейс для всех сущностей
- Автоматическое управление временными метками
- Упрощение работы с датами

**Поля EntityState:**
- `id` (UUID)
- `created_at` (DateTimeImmutable)
- `updated_at` (DateTimeImmutable)

### 3. Использование контекстных логгеров

**Решение:** Использование контекстных логгеров через сервисный тег.

**Обоснование:**
- Четкое разделение логов по функциональности
- Упрощение отладки и мониторинга
- Возможность фильтрации логов

**Логгеры:**
- `wildberriesSupportLogger` - логи поддержки
- `wildberriesManufactureLogger` - логи модуля производственных процессов

### 4. Генераторы для больших объемов данных

**Решение:** Возврат Generator в репозиториях для эффективной обработки больших данных.

**Обоснование:**
- Эффективное использование памяти
- Позволяет обрабатывать большие объемы данных без переполнения памяти
- Улучшенная производительность

**Контекст:**
- AllWbStocksBarcodes
- Другие репозитории, возвращающие большие объемы данных

## Решения по безопасности

### 1. ACL через роли и Voter

**Решение:** Использование ролей и Voter для контроля доступа.

**Обоснование:**
- Четкое разделение прав доступа между FBS и FBO
- Гибкая настройка прав для разных пользователей
- Интеграция с существующей системой безопасности

**Роли:**
- `ROLE_WB_MANUFACTURE_FBS`
- `ROLE_WB_MANUFACTURE_FBO`

**Voter:**
- Для FBS: `Fbs\VoterIndex`, `VoterNew`, `VoterEdit`, `VoterDelete`
- Для FBO: `Fbo\VoterIndex`, `VoterNew`, `VoterEdit`, `VoterDelete`

## Решения по планированию задач

### 1. Использование Symfony Scheduler

**Решение:** Периодические задачи реализуются через Symfony Scheduler.

**Обоснование:**
- Интеграция с существующей системой планирования Symfony
- Возможность настройки интервалов через крон-выражения
- Удобство управления задачами через интерфейс

**Задачи:**
- Обновление заказов (каждые 3 часа)
- Обновление остатков (каждые 3 часа)
- Обновление FBS-остатков (ежедневно)
- Очистка старых заказов (ежедневно в 00:00)

## Решения по обработке ошибок и блокировок

### 1. Обработка HTTP 429 от API

**Решение:** При получении HTTP 429 делается повторная попытка через заданное время.

**Обоснование:**
- Устойчивость к временным ограничениям API
- Предотвращение потери данных
- Автоматическое восстановление после ошибок

**Контекст:**
- GetWbOrdersRequest
- GetWbStocksRequest

### 2. Использование дедупликации

**Решение:** Механизм дедупликации для предотвращения повторной обработки одинаковых данных.

**Обоснование:**
- Эффективность обработки
- Предотвращение дублирования данных
- Устойчивость к повторным вызовам

**Контекст:**
- В обработчиках сообщений

### 3. Откат транзакций при ошибках

**Решение:** При ошибках в UseCase Handler транзакция автоматически откатывается.

**Обоснование:**
- Поддержание согласованности данных
- Предотвращение частично записанных данных
- Упрощение обработки ошибок

**Контекст:**
- Все UseCase Handlers
- Обработка ошибок в CLI командах

### 4. Обработка прерываний

**Решение:** При прерывании команды (Ctrl+C) выполняется корректная остановка с сохранением состояния.

**Обоснование:**
- Предотвращение потери данных
- Возможность возобновления работы
- Корректное освобождение ресурсов

**Контекст:**
- CLI команды (GetWbOrdersLastCommand, GetWbStocksFboCommand, UpdateWbStocksFbsCommand)
